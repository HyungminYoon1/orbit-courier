# ORBIT COURIER — 궤도 임무 연구소

[공개 사이트](https://hyungminyoon1.github.io/orbit-courier/) · [변경·검증 기록](docs/verification.md)

방향과 초기 속도뿐 아니라 **분사 시점과 Δv**를 계획하고, 궤도·에너지·도착 속도를 관찰하는 브라우저 전용 임무 게임입니다. 목적지는 미리 설계된 좌표에 있으며 성공한 발사 경로를 따라 옮기지 않습니다.

## 여섯 개의 서로 다른 임무

| 임무 | 중력원 | 성공 조건 |
| --- | --- | --- |
| 1. 행성 주위를 한 바퀴 돌기 | 1 | 행성 중심 거리 120 ±6%, 원에 가까운 궤도(이심률 ≤0.08)를 한 바퀴 유지 |
| 2. 행성에서 멀리 벗어나기 | 1 | 행성 중심에서 240 이상 멀어지며, 에너지 E >0·바깥 방향 속도 >0 |
| 3. 정거장에 천천히 도착하기 | 2 | 정거장 중심에서 27 이내로, 속도 120 이하로 도착. 낮은 초기 속도 또는 감속 분사 활용 |
| 4. 이웃 행성이 있어도 궤도 유지하기 | 2 | 이웃 행성의 중력을 받으면서도 임무 1의 궤도 조건 유지 |
| 5. 행성 곁을 지나 정거장에 도착하기 | 3 | 행성 중심 거리 120 이내로 접근한 뒤 140 밖으로 나옴. 그동안 분사 없이 방향을 20° 이상 바꾸고, 정거장 중심에서 30 이내·속도 250 이하로 도착 |
| 6. 더 큰 궤도로 옮겨가기 | 1 | 행성 중심 거리 90에서 출발해 160 ±6%, 원에 가까운 궤도(이심률 ≤0.08)를 한 바퀴 유지 |

궤도 조건을 벗어나면 누적 회전은 0으로 돌아갑니다. 임무 6은 타원 궤도로 목표 반경에 잠깐 닿는 것만으로 성공하지 않습니다. 성공하면 다음 임무가 열립니다. 원리 힌트와 참고 계획 적용을 제공하므로 처음 접하는 사람도 성공 비행을 관찰한 뒤 변수를 바꿔 실험할 수 있습니다.

## 조작과 피드백

- 캔버스 드래그 또는 각도·초기 속도 조절기. 0° 오른쪽, −90° 위쪽. 캔버스 방향키로 각도/속도 조절, Space로 실행·일시정지.
- 1회 예약 분사: Δv −80–80, 시점 0–20. 양수는 진행 방향 가속, 음수는 감속, 0이면 분사하지 않음. 감속은 속도 0에서 멈추며 역방향으로 뒤집지 않음.
- 예상 궤적 켜기/끄기, 실제 비행 궤적, 최근 3회 실행 궤적 비교, 분사·근접 통과 위치 표시.
- 속도·반경·비에너지·이심률 계기와 임무 진행률, 구체적인 종료 이유. 예상 결과는 실행 기록과 구분.
- 실행 종료 후 실제 표본의 거리·목표와 signed 오차 시간 그래프. 궤도·탈출은 행성 중심 거리, 정거장 도착은 정거장 중심 거리. 허용 반경과 실제 분사 시점 표시. 과속 실패는 정거장 진입 당시의 판정 속도로 설명합니다.
- 1×/2×/4× 재생, 일시정지·재개, 화면 이탈 자동 정지, 다시 조준, 현재 임무 초기화.
- 최근 코드 선택과 저장한 임무 이어하기. 새로고침은 마지막 코드·임무·설정으로 조준 화면을 복원합니다. 비행 재생 자체는 이어가지 않습니다. 새 코드 버튼에서만 명시적으로 새 판을 만듭니다(첫 사용·유효 기록 없음 제외).

## 물리 모델과 한계

900×560 공간에서 고정된 중력원 1–3개의 역제곱 중력을 합산합니다. Velocity Verlet 방식, 시간 간격 1/120, 최대 4,800단계(모형 시간 40), 화면 표본 간격 1/60입니다. 렌더링 속도는 판정에 영향을 주지 않습니다. 이동 선분과 행성 반경+우주선 반경 5의 교차로 충돌을 판정합니다.

거리·속도·시간은 모두 **모형 단위**입니다. 실제 우주 관측값·항법·장기 궤도 안정성 검증이 아닙니다. 행성은 움직이지 않으므로 근접 통과로 방향이 바뀌는 모습만 재현하며, 이동 행성의 에너지 전달을 재현하지 않습니다. 근접 통과 구역 안의 분사는 해당 통과 인증을 무효화합니다. 다중 중력원에서 화면 이심률은 중심 행성에 대한 순간 이체 근사입니다.

총 비에너지는 `v²/2 − Σ(μ/r)`입니다. 화면의 E와 탈출 판정은 초기 총 비에너지 + 실제 분사의 에너지 변화량을 사용합니다. 보존계에서 발생하는 작은 수치 적분 오차 때문에 정확히 E=0인 발사가 탈출로 오인되지 않도록 했습니다. 탈출 판정의 양수 허용오차는 1e-6입니다. 표본에는 위치·속도로 재계산한 에너지와 최대 상대 오차도 남습니다.

코드는 설계된 배치를 상하 반전하고 좌우로 −12/0/+12 이동하는 6개 변형 중 하나를 선택합니다. 같은 버전·코드는 같은 배치이며 서로 다른 코드가 같은 배치를 가질 수 있습니다. 무제한 무작위 항로나 천체계 생성기는 아닙니다.

## 실행과 검증

Node.js 22 이상. 외부 런타임 의존성 없음.

```sh
npm run dev -- 0
npm test
npm run check
```

개발 서버는 loopback에서 `dist/`만 제공합니다. 모델 시험은 원궤도 해석값, 힘의 합산, 에너지, 탈출 경계, 연속 유지, 충돌, 과속 진입, 근접 통과, 예약 분사와 유한 실행을 각각 검증합니다. 브라우저 조작·화면 QA와는 별개입니다. 이번 변경의 증거는 [검증 기록](docs/verification.md)에 구분했습니다.

main에 푸시하면 기존 GitHub Actions가 테스트·검사 후 dist를 Pages에 배포합니다. 로컬 시험·원격 CI·공개 사이트 검증은 검증 기록에서 구분합니다.

## 점수·저장·개인정보

성공 점수는 `1500 − (초기 속도 + 실제 실행 분사 |Δv|)×2 − 시간×6 − 추가 시도×45 − 힌트 120`을 반올림하며 최저 50점입니다. 원리 힌트/참고 계획은 같은 임무에서 한 번만 120점 감점됩니다. 실패 점수는 0입니다.

`orbit-courier-v2`에 해금, 코드·임무별 최고 점수 최대 100개, 최근 코드 최대 8개, 독립 완료 임무 최대 6개를 저장합니다. 최근 코드는 1–40자 영문·숫자·하이픈으로 제한하며 마지막 임무·4개 발사 입력·시도 수(최대 1,000,000)·힌트 여부를 보존합니다. 같은 코드 중복은 제거하고 최신 사용 순서로 보존합니다. 시간 기반 기록이나 비행 궤적은 저장하지 않습니다. 원시 읽기는 65,536자로 제한합니다. 새로고침만으로 감점이 사라지지 않으며 명시적 임무 초기화는 기존처럼 현재 계획의 설정·시도·힌트를 초기화합니다.

독립 완료는 실제 실행에 성공하고 현재 계획에서 힌트/참고 계획을 사용하지 않은 임무만 집계합니다. 같은 임무를 여러 코드에서 완료해도 하나이며 과거 최고/해금에서 추정하지 않습니다. 기기 내 갤러리 키 `web-lab-progress-v1`에는 `orbit-courier: {completed, total: 6, updatedAt}`만 공유합니다. private 저장 성공 뒤 실제 현재 ISO 시각으로 갱신하며 코드·입력·궤적·이름은 제외합니다. 15개 서비스 allowlist·8,192자·정수 범위를 검증하고 타 앱의 유효 집계는 보존합니다. 초기 화면·예상·도움 받은 성공·실패에서는 요약을 쓰지 않습니다. 같은 origin에서만 공유됩니다.

과거 v1 기록은 가져오지 않으며 사용자가 삭제할 때까지 남습니다. ‘구버전 포함 내 기록 삭제’는 v1/v2와 갤러리의 자기 항목만 제거합니다. 저장 실패 시 알림을 표시하고 현재 세션에서 계속 사용할 수 있습니다. 잘못된 공유 JSON은 덮어쓰지 않습니다.

계정, 분석 도구, 외부 AI API, 클라우드 저장, 전체 사용자 랭킹, 백엔드, Neon은 구현하지 않았습니다. CSP `connect-src 'none'` 유지. 공개 클라이언트의 참고 계획·점수는 공식 경쟁 인증에 쓸 수 없습니다.
