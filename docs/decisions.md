# 결정 기록

## D01 — 독립 정적 사이트

- 대안: 하나의 사이트 / 별도 서버 기반 사이트 / 독립 정적 사이트.
- 결정: 독립 저장소, 브라우저 JS, 외부 런타임 의존성 없음, dist만 배포.
- 이유: 기존 Pages 운영 방식 유지, 개인정보·운영비 최소화.
- 영향: package.json, dist/, workflow, architecture.md.

## D02 — 내 기기 기록과 전체 랭킹 구분

- 맥락: 사용자 랭킹 서버는 구축 의견 요청이며 신규 DB는 꼭 필요할 경우에만 허용.
- 대안: 즉시 DB 생성 / 가짜 랭킹 / 기기 내 기록과 서버 제안 분리.
- 결정: 현재 게임·학습 기록만 브라우저에 저장, 기록 삭제 제공. 외부 전송·계정·전역 랭킹 없음. 서버 제안은 구현 상태와 분리.
- 이유: Neon은 DB이며 공개 점수 제출을 검증할 API가 별도로 필요. 비용·보존·위변조 검증을 먼저 정해야 함.
- 영향: core.js, app.js, README.md.
- 후속 검토: 서버 권위 재현/런 티켓/속도 제한과 무료 한도 확정 후 연결.

## D03 — 재현 가능한 도전 코드

- 맥락: 반복 플레이는 무작위, 친구와 같은 문제·판 비교는 동일 조건 필요.
- 대안: Math.random만 사용 / 모든 판 고정 / seed 기반 생성.
- 결정: 새 판은 crypto 기반 seed; 같은 버전·설정·seed면 같은 초기 조건. 입력은 길이·문자 제한. 게임별 규칙 검증과 생성 시험.
- 영향: model, core, app, tests.
- 후속 검토: 클라이언트 점수는 전체 랭킹 증거로 신뢰하지 않음.

## D04 — 규칙과 작업 화면

- 맥락: 시각적인 소개보다 실제 학습·플레이 완주가 중심인 서비스 요청.
- 대안: 공통 카드형 소개 사이트 / 프로젝트별 직접 조작 화면.
- 결정: 고정 시간 간격 물리 계산과 애니메이션을 분리했습니다. 생성기는 후보 경로를 검증한 뒤 그 경로에 목표를 배치합니다. 무작위 위치로 인해 풀 수 없는 판이 나오는 것을 막고, 재현 시험에 사용할 도달 경로를 보관합니다. 이 정보가 공개 클라이언트에 있으므로 경쟁 인증 자료로 삼지 않습니다.
- 이유: 학습과 플레이 결과를 재현하고 확인할 수 있게 함.
- 영향: dist/src/, dist/index.html, dist/styles.css, test/, README.md.
- 후속 검토: 공개 URL에서 조작과 작은 화면 검증. 기록 보존 범위 변경은 별도 결정 기록 필요.

## D05 — 고정 목표를 가진 궤도 임무 실험실 (2026-10-09)

- 맥락: 각도·추진력만으로 배송하는 반복성과 무엇을 검증했는지 불명확하다는 사용자 피드백. 이번 요청은 로컬 구현·시험만 승인했으며 배포·원격 변경·백엔드를 허용하지 않음.
- 대안: 기존 성공 경로 위의 목표 배치 유지 / 자유 무작위 천체계 / 고정 목표와 독립 판정의 설계된 임무.
- 결정: D04의 ‘후보 경로에 목표를 배치’ 결정을 v2에서 대체. 원궤도·탈출·속도 제한 배송·섭동 궤도·플라이바이 배송·예약 분사 전이 6임무. 목표 좌표와 조건을 먼저 정의하고 참고 계획의 성공 여부를 별도 시험. seed는 상하 반전과 좌우 이동의 6개 기하학적 변형만 선택하며 그 한계를 명시.
- 이유: 성공 경로 하나의 재현으로 물리 규칙을 검증했다고 주장하지 않고, 사용자가 관찰해야 할 반경·이심률·에너지·도착 속도·통과 조건을 구분하기 위함.
- 영향 파일: dist/src/model.js, dist/src/app.js, dist/index.html, dist/styles.css, test/model.test.js, README.md.
- 후속 검토: 메인 담당자의 실제 브라우저 조작·모바일 가독성 QA. 신규 임무 추가 시 목표를 고정한 채 독립 성공/실패 시험 필요. 원격 공개는 이번 범위 밖.

## D06 — 유한 보존계 모델과 1회 예약 분사

- 맥락: 지속 궤도·탈출을 배송 충돌 검사만으로 판정할 수 없음. 고정 행성을 실제 이동 행성의 중력도움으로 오인할 위험도 있음.
- 대안: 기존 softened Euler / 움직이는 천체의 N체 모델 / 고정 천체의 역제곱 합산과 Velocity Verlet.
- 결정: model.js에서 1/120 간격, 최대 4,800단계로 적분. 반경+우주선 크기 선분 충돌. 원궤도는 목표 반경 ±6%, 중심 기준 이심률 ≤0.08을 연속 한 바퀴 유지하며 중간 이탈 시 초기화. 탈출은 지정 경계·바깥 방향 속도·초기 E+분사 변화량 >1e-6을 모두 요구. 다중 중력원 잠재에너지를 모두 합산.
- 결정: 발사 전에 시점과 순/역방향 Δv를 예약해 1회 실행. 역방향 분사는 정지까지만 허용. 플라이바이 통과 중 분사하면 해당 통과 인증을 거부하여 엔진으로 꺾인 방향을 중력만의 효과로 채점하지 않음.
- 이유: 재현 가능한 유한 계산, 알려진 해석값·보존량으로 독립 시험 가능. 수치 적분 오차로 E=0이 양수가 되는 거짓 탈출 성공을 차단. 실제 길이·시간·관측치를 가장하지 않음.
- 영향 파일: dist/src/model.js, test/model.test.js, dist/src/app.js, dist/index.html, README.md.
- 후속 검토: 고정 천체의 방향 전환만 구현. 이동 행성의 에너지 교환·장기 궤도 안정성·현실 항법 검증은 범위 밖. 화면 이심률은 중심 천체에 대한 순간 이체 근사임을 유지.

## D07 — 로컬 점수 버전과 관측/계획 구분

- 맥락: v1의 10배송 점수와 v2의 6임무 점수는 의미가 다르며, 미리 계산한 예상 경로를 실제 실행 기록처럼 표시해서는 안 됨.
- 대안: 기존 기록을 그대로 해금에 사용 / 기존 기록 자동 삭제 / 독립 v2 키와 명시적 삭제.
- 결정: v2 해금과 최고 기록 최대 100개는 orbit-courier-v2 키 사용. v1 기록은 읽어 합치지 않고 자동 삭제하지 않음. 사용자 ‘내 기록 삭제’ 동작은 두 버전 키 모두 삭제. 궤적은 메모리에 최근 3회만 유지. 외부 전송·백엔드·계정·네트워크 접근은 추가하지 않음.
- 결정: 예상 궤적은 파란 점선 및 ‘예상 결과’, 실행은 연두 실선, 이전 실행은 회색 점선. 예상 경로로 점수·해금을 기록하지 않음. 동일 순수 시뮬레이션을 재생하며 1×/2×/4×는 시각 재생만 변경. 실패 시 원인·최종 계기를 표시. 임무 초기화는 현재 시도/궤적만 초기화.
- 이유: 오래된 사용자 데이터를 임의 삭제하지 않으면서 새 규칙의 성취를 구분. 개인정보 저장 범위와 정적 호스팅 경계 유지.
- 영향 파일: dist/src/app.js, dist/index.html, dist/styles.css, README.md, docs/verification.md.
- 후속 검토: 브라우저 저장 차단·재로딩·두 키 삭제, 자동 일시정지, 보조기술/모바일 조작을 메인 QA에서 확인. 모델 시험이나 정적 검사를 브라우저 검증으로 대신 표기하지 않음.
